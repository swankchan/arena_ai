# 灣仔政府大樓 / Wanchai Tower

Photo-directed exterior at 12 Harbour Road, based on the saved research in `references/hongkong/wanchai-tower/`. The OSM v14 ring is used for the footprint (© OpenStreetMap contributors, ODbL); CTBUH gives 136.5 m and 32 storeys, while OSM tags 137 m and 33 levels. A continuous base samples local DTM (5 m at the tower centre); this is not a surveyed construction datum.

The rendered exterior interprets the two long facades' pale solid piers and twelve bands of narrow recessed windows, the dark transfer band and upper blue-grey curtain-wall grid. It includes two estimated projecting glazed entrance pavilions, dark portals, bilingual wall lettering, stepped approaches, handrails, tactile bands and emissive night windows/entrance lights. Pane distribution, dimensions, glass colour, position of lights, and stairs are approximations rather than measured plans. Entrances are closed: interiors and the full surrounding forecourts, landscaping, side access and bridge connections have not been modelled.

A 1 m local road grid with 0.2 m road-query margin checks the tower colliders and estimated step footprints against mapped roads; half-metre approach samples also check the neighbouring Immigration and Revenue Towers, and source street-lamp poles. These are discrete tests, not proof of continuous clearance or surveyed positions. Stair heights are selectable for pedestrians only and do not replace a road surface. No in-game day/night visual or driving inspection has yet been performed.

## Three.js Editor export prototype

The home screen can download a standalone Three.js Object JSON generated from the same tower builder without starting the city. File → Import in the Three.js Editor is the intended workflow. The tower is centred at the origin for editing; the export does not replace the in-game building. Canvas lettering is embedded as a data URL. The isolated build substitutes the previously sampled 5 m site datum, then removes the group translation; it does not load city roads or terrain.

For broad Editor compatibility the export converts node materials on this separate object into ordinary MeshStandardMaterial with vertex colours, roughness and metalness. Dynamic TSL night emission is **not** reproduced; the `aLit` geometry attribute remains in the file for possible later work, but is not connected to an emissive material. Colliders, terrain interaction, and gameplay logic are not exported. Window and façade geometry is merged, so individual windows cannot simply be selected as separate objects. The result is a prototype, not a lossless round trip back into the game. Rebuild the isolated bundle with `npm run build:runtime` after editing the tower or its helpers.

### Experimental TSL JSON

A separate button exports the same isolated model with its original node materials and the serialized TSL graph in the same JSON. `uInteriorGlow` is captured at 1.4 (night); it is a static uniform snapshot, not the game's day/night controller. It does not replace or alter the game. The bundled Three.js Editor r187's [JSON import](https://github.com/mrdoob/three.js/blob/r187/editor/js/Loader.js) uses ordinary `ObjectLoader`, not `NodeObjectLoader`, so importing this experimental file directly into that Editor cannot restore these node materials. Use the ordinary export for Editor editing. The vendored 187dev `NodeObjectLoader` also tries to assign a read-only node UUID; our automated graph test has to patch the loader's node constructors to work around that upstream issue. This is not evidence that the unmodified loader or Editor can display the TSL file. Rendered night lighting and cross-version compatibility have not been visually verified.

## Building chooser

The home screen now offers a searchable catalogue of dedicated active-scene structures (including some complexes and parks), not every generic building in the territory. Each selection calls its existing builder in a temporary scene with the same terrain options as the game, rather than building the entire Hong Kong scene. Wan Chai Tower retains its smaller isolated bundle; other choices may load the shared terrain, road and landmark data required by their modules and can take longer. Large exports can be hundreds of megabytes. The Salisbury / YMCA is not offered because a geometry bounds check detected non-finite vertices; do not silently export a corrupt model.

The chooser moves the exported structure as a whole near the origin. Complexes are exported as their existing whole builder, not necessarily one independently editable building. Editor-compatible exports approximate node shaders using standard/basic materials and preserve vertex colours where available; procedural facade details, texture nodes, transparency, appearance and emissions may differ. TSL JSON remains experimental and has the Editor and NodeObjectLoader limitations noted above. ObjectLoader round trips check structure, but are not visual validation in the Editor or the game.
