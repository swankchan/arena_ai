# Hong Kong TIS_16 traffic-aids slice

## Coverage and provenance

This directory contains the persisted **Statue Square core demonstration**, not a whole-city extract.

- WGS84 bbox: `114.1585,22.2807,114.1612,22.2827` (west, south, east, north).
- Publisher: **Hong Kong SAR Government Transport Department**.
- Dataset: [Traffic Aids Drawings (2nd generation), TIS_16](https://data.gov.hk/en-data/dataset/hk-td-tis_16-traffic-aids-drawings-v2).
- Retrieved: **2026-10-29**.
- Access route: the public Esri China (Hong Kong) mirror, item [`942c27b1c99c4369a5d1483f706f29ce`](https://www.arcgis.com/sharing/rest/content/items/942c27b1c99c4369a5d1483f706f29ce?f=pjson), which identifies its TD source update as **2026-04-24**. This is a dated mirror, not a claim to be the latest monthly government extract.
- `source.json` records the exact reproducible FeatureServer query URL for each layer, the bbox, layer ID, feature count and SHA-256 of the persisted response. The build refuses a changed file whose hash or count no longer matches the manifest.

The raw GeoJSON remains the source of truth. Its coordinates and `OBJECTID` values are not hand-edited. `tools/cities/hongkong/traffic-aids.mjs` checks the hashes and transforms the same vertices into the local Statue Square frame at millimetre output precision. `js/hk-geodata.js` is generated by `tools/build-city.mjs hongkong`; do not edit that module by hand.

## Official versus derived geometry

**Official/source geometry:** feature IDs, point locations, line vertices and crossing-stripe ring extents, followed by the coordinate transform alone. The original responses stay in this directory.

**Derived rendering geometry:** TPDM paint widths and dash modules, mitered strip triangles, triangulation of the already closed crossing rings, yellow-box line widths, coincident signal-point assemblies, signal-head dimensions and road-relative facing. These do not create new surveyed locations.

- Both sister road-mark layers are read. `RM1002` breaks the right line and `RM1003` the left line relative to each part's digitised direction. A double line's `spacing` is the clear gap, not the centre-to-centre pitch.
- No marking is inferred from an OSM centreline or road width. The former procedural Hong Kong lane-dash generator has been removed. Outside this small source slice there is currently no surveyed paint layer; that is incomplete coverage, not evidence that real streets have no markings.
- Only closed crossing faces are painted. Four loose edges may close a face, but crossing outlines and ladder gaps are never flooded. The core's 72 rings are all closed, convex stripes; no faces touch.
- A crossing is white only with explicit zebra evidence (`ZEBRA4` or nearby surveyed `ZIGZAGL/R`). This core has no such zigzag, so its ten crossings render as **yellow signal-crossing stripes**, not invented white zebras.
- Yellow-box features use their surveyed line/hatch runs. No filled rectangle is substituted for the empty polygon layer. Non-closed runs are emitted segment by segment to avoid miter bow-ties at digitised backtracks.
- `REFNAME` is only a head/not-head gate (`P` or `S` plus digits and optional `L/R`). The 82 admitted points form **44 derived coincident-point assemblies** at 0.75 m linkage; original IDs, codes and angles remain in `GEO.trafficAids`. The assembly centroid, one head per assembly and its dimensions are rendering decisions, not extra government attributes.
- TD's `ANGLE` is preserved but is not consumed as a validated facing. Facing is derived from the nearby road and Hong Kong's left-hand traffic. Signal lenses are deliberately **unlit**: this layer supplies no official phase group, stage order, timing or clearance interval, and no AI signal cycle is invented.

## Style-audit note

The commonly used CT174/51 rows (double white lines, stop/give-way lines, chevrons, hatching, lane/warning lines) have explicit width/module transcriptions. For the less common `RM1006`, `RM1007`, `RM1049` and `RM1107`, the current renderer uses the continuous-versus-representation-layer distinction and the equal mark/gap proportions visible in the standard-drawing vectors. Their selected widths (`0.20`, `0.20`, `0.20`, `0.10` m) and one-metre modules still need an independent text-sheet audit. Their **surveyed geometry is official; these particular style parameters are provisional** and are not presented as independently verified dimensions.
